# 実地地球オーバーマップパケット

`overmap_geo` の定義は、手続き的ノイズ パイプラインを実世界の地域に置き換えます:
実際の土地被覆、実在する河川、そして実際の OSM 道路がオーバーマップに描かれ、
都市は実座標に配置されます。データは JSON 定義の隣にある 1 つのバイナリ サイドカー
ファイル (`.cmap`) に格納されています。

実地地球生成は `GEOGRAPHY_MODE` ワールド オプションでゲートされています: パケットは
このオプションが `real_earth` に設定されている場合のみ使用されます。既定の
`procedural` モードは、従来のノイズ生成器をそのまま維持します。

地域を生成する最も簡単な方法は、`tools/geo` の変換スクリプトです
([変換器](#変換器) 参照)。このスクリプトは、バウンディング ボックスについて ESA
WorldCover の土地被覆と OpenStreetMap の河川・道路・都市をダウンロードします。

## JSON 定義

| 識別子 | 説明 |
| --- | --- |
| id | (_必須_) パケットの一意の ID。 |
| file | (_必須_) この JSON ファイルからの相対パスにある `.cmap` バイナリ サイドカーのパス。 |
| zones | (_任意_) ゾーン クラス インデックスごとの生成ルール (`"0"`..`"255"`、10 進キー)。 |
| river | (_任意_) パケットの河川ポリラインの描画方法。省略は「河川なし」を意味します。 |
| cities | (_任意_) 実世界の都市配置。座標はパケット アンカー基準で、河川頂点と同じ座標空間です。 |

```json
[
  {
    "type": "overmap_geo",
    "id": "geo_new_england",
    "file": "geo_new_england.cmap",
    "zones": {
      "1": { "paint": "forest" },
      "2": { "paint": "lake_surface" },
      "3": { "paint": "forest_water" }
    },
    "river": { "paint": "river_center", "width": 3 },
    "cities": [
      { "name": "Boston", "x": 5964, "y": 2497, "size": 16, "finale": true }
    ]
  }
]
```

### zones

各メンバーはバイナリ マスクのゾーン クラス インデックスです。現在認識される
メンバーは 1 つです:

| 識別子 | 説明 |
| --- | --- |
| paint | (_任意_) ゾーンが覆うすべてのセルに描画される基本オーバーマップ地形。省略すると、そのゾーンは既定の地形をそのまま残し、通常の手続きパスが引き続き細部のテクスチャを提供します。 |

ルールのないゾーン クラスも描画されずに残ります。

### river

| 識別子 | 説明 |
| --- | --- |
| paint | (_必須_) 河川ポリラインに沿って描画されるオーバーマップ地形。 |
| width | (_任意_) OMT セル単位の既定川幅。既定は 1、最小は 1 です。固有の幅を持たない川のみに使われ、変換器は OSM の `width` タグから川ごとの幅を採取してバイナリ パケットに格納します。 |

### cities

都市シードの配列です:

| 識別子 | 説明 |
| --- | --- |
| name | (_任意_) 都市ラベルとして表示される実際の地名。 |
| x, y | (_必須_) 都市の中心。パケット アンカー (マスクの北西隅) 基準、OMT セル単位。 |
| size | (_任意_) `CITY_SIZE` ロールと同様の、OMT セル単位のバニラ都市半径、1..16。既定は 1。 |
| finale | (_任意_) ここで特別なフィナーレ配置 (vault など) を試みるかどうか。既定は false。 |

都市は実座標に、通常の手続き都市機構で配置されます。パケットが都市ガイダンスを
提供している間、バニラの `place_isolated_cities` パスはスキップされ、手続き的
都市が実際の地理の上に重ねて現れることはありません。

## バイナリ パケット フォーマット (`.cmap`)

サイドカーは `src/overmap_geo.cpp` の `overmap_geo::parse_binary` がパースする
リトル エンディアン stream です。現在のバージョンは 3 で、それより古いバージョンは
ロード時に拒否されます。その場合は変換器で地域を再生成する必要があります。
変換器はさらに、全文ポリラインを Douglas-Peucker (0.5 OMT = 12 m 許容) で
簡略化し、頂点デルタを zigzag varint で格納するため、ニューイングランド規模の
リージョンでもパケットは約 1 MB に収まります。

1. `u32` マジック `"BNCG"`
2. `u16` フォーマット バージョン (3)
3. `i32` アンカー X, アンカー Y — 最初の (北西の) マスク セルの絶対 OMT 座標。
   ファイル内のすべての頂点座標は、このアンカー基準のデルタで与えられます
4. `u16` セル スパン — マスクのマクロ セル 1 辺が覆う OMT セル数
   (変換器は 8 を使用します。すなわち 8×8 OMT = 各 24 m = マクロ セルあたり 192 m)
5. `u32` マスク セル X, Y — マクロ セル単位のマスク寸法
6. `u16` ゾーン数 — ゾーン クラス テーブルのサイズ
7. `u16` 河川数
8. ラン レングス エンコードされたマスク。北西隅から行方向に
   `[u8 ラン長, u8 ゾーン インデックス]` のバイト ペアを繰り返し、
   `cells_x * cells_y` 個のセルが埋まるまで続きます。ラン長 0 と未定義の
   ゾーン インデックスは拒否されます
9. 河川ポリライン。順に並びます: `u16` 頂点数 (2 以上)、`u8` 川幅 (OMT セル単位、
   0 = JSON `river` ルールの幅をフォールバックとして使用)、続いて各頂点について
   zigzag-varint の X デルタと Y デルタ。最初のデルタはアンカー基準、以降は
   前の頂点基準です
10. 道路ポリライン: `u32` 道路数、続いて各道路について
    `u8` 道路ティア (0..2、それより大きい値は拒否)、zigzag-varint の頂点数
    (2 以上)、そして各頂点について zigzag-varint の X デルタと Y デルタ
    (最初はアンカー基準、以降は前の頂点基準)

最後のセクションの後の余分なバイトは拒否されます。zigzag varint は符号付き
デルタを非負の LEB128 base-128 数 (0, -1, 1, -2, 2 ... を
0, 1, 2, 3, 4 ... に) として格納するため、滑らかなポリラインは座標あたり
1-2 バイトで済みます。

道路ティアはその way の OSM `highway` クラスを表します:

| ティア | 値 | OSM クラス |
| --- | --- | --- |
| highway | 0 | `motorway`, `trunk` (`_link` を含む) |
| main | 1 | `primary`, `secondary` (`_link` を含む) |
| local | 2 | `tertiary` (`_link` を含む) |

## 生成の挙動

パケットは、それがオーバーマップと交差する場合、かつ `GEOGRAPHY_MODE` ワールド
オプションが `real_earth` に設定されている場合にのみ使用されます。覆われた
オーバーマップ内では:

* ゾーンはルールに従って描画されます。描画されないクラスは既定の地形と手続き的な
  細部テクスチャを保ちます。
* 覆われたオーバーマップでは、バニラの河川・湖ノイズ パスはスキップされ、代わりに
  パケットの河川が使われます。ポリラインは川ごとの幅で描かれ (幅を持たない川は
  `river` ルールの幅にフォールバック)、バニラの河川と同様に整えられます。
* 道路ポリラインはセル単位でラスタライズされます。水上の道路は橋になります:
  橋区間は高い橋地形にせり上げられて両端にランプが付き、桁の下の水面は
  under-bridge 地形になります。橋区間が水を斜めに横切る場合、バニラの
  bridgehead とランプのロジックが正しく適用されるように、軸平行 (マンハッタン)
  の経路に再構築されます。
* 覆われたオーバーマップではバニラの `place_roads` がスキップされるため、
  手続き的な道路が実際の道路網を横断することはありません。
* 覆われたオーバーマップの端にある道路の端は、`local_road` の `connections_out`
  項目として公開されます。これにより隣の手続き生成オーバーマップは自らの境界で
  実際の道路を受け取り、外側へ延長します。
* 大きな手続き都市のフットプリント (都市シードと半径 8 以上の周辺) 内では、
  `local` ティアの道路が取り除かれ、手続きの街路格子がその領域を担います。
  より高いティアは通過します。
* パケットの都市はバニラの都市機構で配置されます。パケットが都市ガイダンスを
  提供している間、バニラの `place_isolated_cities` パスは無効化されます。

## 変換器

変換器は `tools/geo/make_geo_packet.py` にあり、`rasterio` の入った Python
環境が必要です:

```sh
python3 -m venv .venv && .venv/bin/pip install rasterio
.venv/bin/python tools/geo/make_geo_packet.py \
  --bbox -72.80 42.03 -70.95 42.90 \
  --out-dir ~/.local/share/cataclysm-bn/mods/geo_new_england \
  --mod-id geo_new_england
```

| 引数 | 説明 |
| --- | --- |
| --bbox | (_必須_) 地域のバウンディング ボックス。度単位で `西 南 東 北`。ボックスの中心は絶対 OMT (0, 0) — ワールド スポーン地点にアンカーされます。 |
| --out-dir | (_必須_) 出力 mod ディレクトリ。`.cmap` サイドカー、mod JSON、`.ppm` プレビューを受け取ります。 |
| --mod-id | mod の識別子。生成される JSON に使われます。既定は `geo_new_england` です。 |
| --cache-dir | ダウンロードしたタイルと Overpass 応答のキャッシュ。既定は `~/.cache/cbn-geo` です。 |
| --no-rivers | Overpass の河川/都市クエリをスキップし、`river`/`cities` メンバーを書きません。 |

`.ppm` プレビュー (P6、北向き) は人間が素早く確認するためのものです:
`ffmpeg -i x_preview.ppm x.png` で変換してください。

道路と河川の両ポリラインは、エンコード前に Douglas-Peucker (0.5 OMT = 12 m 許容)
で簡略化され、河川の幅はタグがあれば OSM の `width` タグから採取されます。

データ ソースとライセンス:

* 土地被覆マスク: [ESA WorldCover 10 m 2021 v200](https://esa-worldcover.org)
  3°x3° COG タイル (公開 S3 バケット、必要時にダウンロード)、8×8 OMT (192 m) の
  ゾーン セルに多数決サンプリング。© ESA WorldCover project 2021 / Contains
  modified Copernicus Sentinel data (2021) processed by ESA WorldCover
  consortium — [CC-BY 4.0](https://creativecommons.org/licenses/by/4.0/).
* 河川 (`waterway=river|canal` ポリライン) と都市/町ノード: Overpass API 経由で
  OpenStreetMap から取得。© OpenStreetMap contributors,
  [ODbL](https://opendatacommons.org/licenses/odbl/).
* 道路 (`highway` が `motorway|trunk|primary|secondary|tertiary`、`_link` 含む):
  Overpass API 経由で OpenStreetMap から取得、同じ ODbL 条件が適用されます。
